# BodyMate 全身人体、蒙皮与动作交接

更新：2026-09-12。当前页面：本地 HTTP 服务的项目根目录，现使用 `http://127.0.0.1:4174/`。

## 当前实现

现有 Human Atlas 原始肌肉资产没有骨骼蒙皮。旧实现按整块网格中心分组旋转，跨关节肌肉不能同时跟随两端；早期按顶点位置硬切分权重还会使相邻顶点落到不相关骨骼，出现长条拉裂。

现在页面读取 `assets/anatomy/human-atlas/rigged-body.glb`，包含 415 个肌肉网格、282 个骨骼及相关结构（其中 2 个为髂胫束）、21 个标准驱动关节、1 套共享 skin、3 段 glTF 动画。原有 401 个肌肉的顶点位置逐项保留；补入同一源数据中被误标为 skeletal 的 14 个肌肉结构。全身覆盖头颈、躯干、四肢与手足，继续应用原有外生殖器相关排除规则。

所有结构共享同一坐标和逆绑定矩阵。肌肉归属按名称与整块网格的空间位置确定，再在允许的相邻关节间计算连续权重；不会在顶点跨过 x=0 时切换身体侧别。骨骼硬组织使用所属骨段，髂胫束按腿部组织变形。肌肉运动由标准蒙皮产生，旧的整体旋转分组和独立缩短 shader 已移除。

俯卧撑使用双臂两段逆运动学固定手腕，腿部保持支撑链；手掌参考平面来自原始手部纵轴，掌面向地面、指尖向前，前臂同步旋前。深蹲固定脚部位置，髋膝通过逆运动学求解。弯举使用前臂屈伸，手腕跟随前臂。每个循环首尾连续。

## 用户可用功能

- 输入“做一个俯卧撑”“深蹲”“弯举”，或点击动作示例开始。
- 输入“胸大肌”“三角肌”“肱二头肌”等名称高亮同组肌肉。
- 肌肉、骨骼、透视三种显示模式；拖动旋转、滚轮缩放。
- 暂停/播放、0.5×/1×/1.5×速度、拖动时间进度、肌肉闪烁开关、恢复站立。
- 闪烁强度随动作阶段变化；暂停或系统减弱动态效果时保持稳定颜色。
- 未制作的动作会明确显示当前支持范围。文本入口目前是本地动作匹配，不是任意文本生成动画。

## 参数化动作扩展（2026-09-12）

本轮保留全部真实网格与蒙皮，增加参数化姿态和折叠“动作调整”面板。

| 动作 | 参数 | 演示范围 / 默认值 |
| --- | --- | --- |
| 俯卧撑 | 手距（两腕支撑点距离 / 模型肩宽） | 0.8–1.8 倍 / 1.5 倍 |
| 俯卧撑 | 底部上臂与躯干夹角（投影到躯干平面） | 15–70 度 / 45 度 |
| 深蹲 | 站距（两踝距离 / 模型髋宽） | 0.8–1.8 倍 / 1.2 倍 |
| 深蹲 | 脚尖外展（相对于正前方） | 0–35 度 / 20 度 |
| 深蹲 | 相对基准演示的下蹲幅度 | 60–110% / 100% |

这些范围是当前模型约束，不是人体活动极限或训练建议。模型肩宽采用肩关节间距 0.33m，髋宽采用源图谱双侧髋骨外侧宽度约 0.29m；暂不支持个体体型缩放。

可直接输入：

```text
窄距俯卧撑，夹角45度
俯卧撑，手距1.2倍肩宽，夹角30度
深蹲，站距1.5倍髋宽，脚尖外展30度，深度80%
脚尖外展15度
```

最后一句是在当前深蹲基础上调整。参数需要阿拉伯数字和面板单位；中文数词、错误比例基准和未支持的角度不会被宣称已执行。负重、抬高或单侧等超出范围的指令会提示未支持。超出范围或不落在步长的数字会归一化并显示实际值。

控件松开时重建当前动作的 60fps Three.js 动画轨道，不重新下载网格；旧动画从 Mixer 解除缓存，避免连续调参积累绑定。调参保留当前进度、暂停状态、速度、相机和显示模式。每个动作有三个姿势预设；暂未做双模型并排 A/B 对照。

肌肉提示独立配置主要、辅助、稳定参与的定性颜色权重。手距和部分站距的提示有研究依据；没有把每个肘角、脚尖角和深度机械换算成肌肉受力。内部权重只用于颜色，不是 EMG、肌肉力或增肌百分比。研究依据保存在配置中，不恢复来源侧栏：

- https://pubmed.ncbi.nlm.nih.gov/16095413/ — 窄 / 宽距俯卧撑的短时肌电比较，不是连续角度或长期增肌模型。
- https://pubmed.ncbi.nlm.nih.gov/19130646/ — 六名训练者在部分站距和负重条件下的深蹲肌电；仅作为臀大肌定性趋势。
- https://pubmed.ncbi.nlm.nih.gov/30026952/ — 站距 / 脚尖角影响运动学和关节力矩，不能据此推算单块肌肉力。

姿态求解补充了过近目标与共线极点处理；俯卧撑通过肘部可达圆与目标平面的交线求解底部夹角，接近伸直时采用最近可达姿态。深蹲随站距下调起始骨盆高度，避免腿部伸长；膝部引导方向与脚尖方向联动。实际脚趾检查发现原基准俯卧撑约 6mm 穿地，本轮提高足部支撑高度 7mm，并微调最高点躯干角以保留宽距手臂可达性。

新增 `src/full-muscle/motion-parameters.mjs`（参数、预设、文本解析、肌群提示）、`src/full-muscle/motion-clip.mjs`（动态动画），以及 `test/motion-parameters.test.mjs`。`sampleMotion(id, phase, parameters)` 同时服务 GLB 导出和运行时动画，默认参数已重新烘焙进交付 GLB。新增动作还需在 `parameterDefinitions` / `motionPresets` 注册配置（无参数可为空数组），并提供 `muscleProfileForMotion` 的肌群规则。

自动验收覆盖 36 组参数组合、每组 41 个时刻的支撑点、骨长、掌心和首尾连续性，以及真实 GLB 上 12 组边界组合的动态动画、三角面拉裂采样、脚掌穿地采样及突然翻转。`npm run check` 当前通过 84 项 JavaScript 测试和 30 项 MoonBit 测试，以及生成物一致性和仓库卫生检查。运行 `npm run anatomy:test-rig` 可同时执行资产与参数测试。

本地浏览器验证了文本创建动作、参数追问、两个动作的滑块和预设、超界提示、暂停在 50% 后调参保留进度，以及骨骼显示切换。检查了 1365×900 桌面、820×1000 平板和 390×844 手机断点；桌面提问框保持可达，窄屏展开后无横向溢出且页脚位于内容之后。修正了旧装饰线导致模型面板被程序滚动和窄屏 1000px 高度上限造成页脚重叠的问题。浏览器无捕获到的 error；仍有原先多个 Three.js 包并存的 warning，本轮不重构旧肩颈运行时。

## 文件与构建

| 文件 | 用途 |
| --- | --- |
| `src/full-muscle/rig-definition.mjs` | 关节位置、结构归属、连续权重、姿态求解、动作词表与肌群映射 |
| `scripts/build-rigged-body.mjs` | 验证源文件并导出标准蒙皮 GLB、动画与清单 |
| `assets/anatomy/human-atlas/rigged-body.glb` | 页面实际显示的完整骨骼与肌肉模型，可导入支持蒙皮 glTF 的工具 |
| `assets/anatomy/human-atlas/rigged-body.manifest.json` | 来源、哈希、结构与关节清单 |
| `assets/anatomy/human-atlas/RIGGED_BODY_ATTRIBUTION.md` | 新衍生模型的署名与修改说明 |
| `src/full-muscle/runtime-entry.mjs` | Three.js 加载、AnimationMixer、选取、相机和闪烁渲染 |
| `assets/runtime/full-muscle-root-adapter.js` | 提问入口、动作和播放控件 |
| `assets/full-muscle.css` | 全身模型界面样式 |
| `test/full-body-rig.test.mjs` | 加载真实 GLB 后执行绑定、动作与形变验收 |

```powershell
# 修改关节、权重或动作后，重新导出模型和页面脚本
npm run anatomy:build-rig

# 仅修改渲染器后重新打包
npm run full-muscle:build-runtime

# 实际模型测试；再运行全项目校验
npm run anatomy:test-rig
npm run check
```

初始源数据位于 `prototype/human-atlas-local/local-assets/`，按固定 SHA-256 校验。源目录不存在时，构建器可以从已交付 GLB 中保留的原始静止顶点重新制作骨架与动画；也可以显式运行：

```powershell
node scripts/build-rigged-body.mjs --from-frozen
npm run full-muscle:build-runtime
```

已验证该方式能生成逐字节一致的模型，不需要下载完整源图谱。不要删除已交付的 GLB 和对应 manifest。已有静态 `full-muscles.glb` 和肩颈 GLB 均保留。

## 新增一个动作

1. 在 `motionDefinitions` 增加唯一 id、中文标题、输入别名、时长、宽泛肌群名称与网格名称匹配规则。
2. 在 `sampleMotion` 的支持列表与姿态分支实现这个 id，返回根节点位移及每个关节的局部四元数。全局旋转必须先换算为父关节相对旋转。固定手脚的动作优先复用 `solveTwoBone`，避免直接平移骨段。
3. 动作周期采用 0–1，首尾位姿一致；不要把未实现的 id 默认为另一个动作。动画生成器会采样为 30fps 的标准 glTF 通道。
4. 调整该动作的肌群映射与强度曲线；显示红色表示预设参与肌群，不是传感器测得的肌电。
5. 构建并运行模型测试，在浏览器检查起始、最低/最大角度、中间阶段、暂停、重复播放、恢复站立与骨骼视图。

## 验收证据与边界

自动测试读取页面实际引用的 GLB，并使用同一版本 Three.js 解码和播放。检查全部结构有共享 skin、权重有限且归一化、原始肌肉顶点不变、三个动作能加载、骨长恒定、支撑端位移小于 1mm、掌心向下与指尖向前、手部不穿过地面、抽样真实三角面不出现长条拉裂，以及闪烁在暂停和 reduced-motion 下稳定。全项目校验还检查生成物一致性和原有 MoonBit 行为。

浏览器已逐一检查站立、俯卧撑低位、深蹲低位、弯举最大屈肘位和骨骼显示。界面显示层已为模型与播放控件预留独立空间。

当前是基于真实解剖几何制作的教学动画系统；21 个关节覆盖主要躯干与肢体链。手指随手腕整体运动，脚趾随足部运动，尚未提供逐指抓握、肩胛骨精细滑动、软组织碰撞、医学力学求解或任意动作自动生成。扩展高幅度扭转或复杂接触动作时，需要继续制作相应动作约束和检查局部权重。
